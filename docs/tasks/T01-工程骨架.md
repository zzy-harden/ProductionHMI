> 面向第一次接触 C++ 工程、Qt 和 CMake 的学习记录。不要试图一次记住所有 CMake 语法，本节只掌握项目里真正会反复用到的部分。

## 1. 这一任务解决什么问题

写业务代码之前，先让项目满足三件事：

1. Qt Creator 能打开；
2. CMake 能知道“哪些源码组成哪个目标”；
3. 最小 Qt 窗口能启动。

如果这一步不稳定，后面新增 Modbus、数据库、测试时很难判断问题到底来自业务代码还是工程配置。

当前入口文件是：

```text
src/app/main.cpp
```

根构建文件是：

```text
CMakeLists.txt
```

## 2. 必会：C++ 工程不是“几个 .cpp 文件放一起”

一个稍正规的 C++ 项目至少要区分：

```text
源码        src/
测试        tests/
配置        config/
文档        docs/
第三方库    third_party/（后续需要时）
构建规则    CMakeLists.txt
```

源码负责实现程序；CMake 负责告诉编译器：

- 用哪个 C++ 标准；
- 编译哪些 `.cpp`；
- 生成库还是可执行程序；
- 链接哪些 Qt 模块；
- 测试程序怎么构建。

面试中如果问“CMake 是干什么的”，可以答：

> CMake 本身不是编译器，它负责生成构建系统，并描述 target、源码、头文件搜索路径、编译选项和链接依赖。Windows 上最终通常交给 MSVC 编译。

## 3. 必会：`add_library` 和 `add_executable`

当前工程中有两个重要 target：

```cmake
add_library(ProductionHMI_core STATIC ...)
add_executable(ProductionHMI src/app/main.cpp)
```

可以把它理解为：

```text
ProductionHMI_core
    = 核心业务代码组成的静态库

ProductionHMI
    = 最终启动的桌面程序
```

为什么不把所有 `.cpp` 全塞进一个 exe？

因为后续测试程序也要复用核心代码：

```text
                 ┌─ ProductionHMI.exe
core 静态库 ─────┤
                 └─ test_xxx.exe
```

这样测试业务逻辑时，不需要启动整个 GUI。

### 面试记忆点

`target_link_libraries(A PRIVATE B)` 的意思不是“包含 B 的头文件”，而是：

> A 在链接阶段依赖 B。

头文件搜索路径则由 `target_include_directories` 管理。

## 4. 必会：为什么指定 C++17

当前工程：

```cmake
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
```

本项目后面会使用 C++17 的：

- `std::variant`；
- `std::optional`；
- 更规范的类型与资源管理方式。

`CMAKE_CXX_EXTENSIONS OFF` 表示尽量使用标准 C++，减少依赖某个编译器私有扩展。

## 5. 必会：最小 Qt 程序怎么运行

`src/app/main.cpp` 的核心流程：

```cpp
QApplication app(argc, argv);
QWidget window;
window.show();
return app.exec();
```

对初学者最重要的是理解 `app.exec()`。

Qt GUI 不是：

```text
main() 从上到下执行完 → 程序结束
```

而是：

```text
初始化 QApplication
      ↓
创建窗口
      ↓
show()
      ↓
进入事件循环 app.exec()
      ↓
不断处理鼠标、键盘、定时器、网络事件、信号槽
```

这就是以后为什么强调“不能在 UI 线程里做阻塞网络操作”。

如果 UI 主线程卡在一个耗时函数里，事件循环无法继续处理重绘和点击，界面就会表现为“未响应”。

### 面试高频问法

**Q：Qt 界面为什么会卡死？**

答题核心：

> GUI 事件循环运行在主线程。如果在主线程执行阻塞 IO 或长耗时任务，事件循环无法及时处理窗口消息和重绘，因此界面会卡住。项目后续会把 Modbus 通信放到独立线程。

## 6. `AUTOMOC / AUTOUIC / AUTORCC` 是什么

当前 CMake 开启：

```cmake
set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTOUIC ON)
set(CMAKE_AUTORCC ON)
```

初学阶段只需知道：

- `AUTOMOC`：自动处理 Qt `Q_OBJECT` 相关代码生成；
- `AUTOUIC`：自动处理 `.ui` 文件；
- `AUTORCC`：自动处理 Qt 资源文件 `.qrc`。

现在项目还没大量使用这些能力，但提前启用可以避免后续每加一个 Qt 类都手工配置生成步骤。

## 7. 本任务主要文件

| 文件 | 类型 | 作用 |
|---|---|---|
| `CMakeLists.txt` | 新建/持续修改 | 定义项目、target、Qt 依赖和测试 |
| `src/app/main.cpp` | 新建 | GUI 程序入口 |
| `.gitignore` | 新建 | 排除 build、IDE 临时文件等 |
| `README.md` | 新建 | 项目说明和构建方式 |

注意：T01~T03 的历史代码后来一起整理进了 PR #1，所以 Git 历史中不是严格的“一任务一 PR”；从后续任务开始会保持任务粒度。

## 8. 你应该亲手做一次

在 Win11 + Qt Creator 中：

1. Clone 仓库；
2. Qt Creator 选择“Open File or Project”；
3. 打开根目录 `CMakeLists.txt`；
4. 选择 Qt 6 + MSVC 2022 x64 Kit；
5. Build；
6. Run。

命令行等价流程：

```powershell
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --config Debug --parallel
```

如果能看到 `Production HMI - Project Skeleton` 窗口，说明最基本工程链路成立。
